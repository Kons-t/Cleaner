# cleaner

Консольная утилита для macOS, которая чистит типовой «мусор», накапливающийся на диске: кеши Go, Homebrew, Docker, DaVinci Resolve, логи приложений, файлы `.DS_Store` и сохранённые ответы HTTP-клиента JetBrains IDE.

Управление — только через интерактивное меню (стрелки ↑/↓ + Enter). Вводить пути или флаги руками не нужно.

## Что умеет чистить

| Модуль | Что делает | Путь по умолчанию |
|---|---|---|
| Go: кеши | `go clean` для build/mod/test/fuzz кеша, выбор одного/нескольких/всех | `GOCACHE`, `GOMODCACHE` (из `go env`) |
| IDEA: HTTP-ответы | Удаляет сохранённые `.json`-ответы HTTP-клиента JetBrains IDE | `<WorkDir>/**/.idea/httpRequests/*.json` |
| Homebrew | `brew cleanup` (сначала показывает `--dry-run`) | — |
| Docker | `docker system prune -f` (без `-a` и `--volumes`, именованные тома и используемые образы не трогает) | — |
| Логи | Удаляет файлы логов приложений | `~/Library/Logs` |
| `.DS_Store` | Удаляет мусорные файлы Finder | весь домашний каталог (`~`) |
| DaVinci Resolve | Удаляет файлы render cache | `~/Movies/CacheClip` |
| Xcode DerivedData | Удаляет папки проектов (build-артефакты, индексы) целиком | `~/Library/Developer/Xcode/DerivedData` |

Для каждого модуля порядок действий одинаковый: программа показывает, что нашла (размер, количество файлов/директорий), просит подтверждение и только после этого удаляет. Ни одно действие не выполняется без явного `Yes` в подтверждении.

При запуске приложение само проверяет, какие инструменты/директории реально есть на устройстве (`go`, `brew`, `docker` в `PATH`; директории `WorkDir`, `LogsDir`, `.DS_Store`-корень; установлен ли DaVinci Resolve). Пункты меню, для которых ничего не найдено, в список не попадают — над меню печатается сообщение, какие модули доступны именно на этой машине.

## Требования

- macOS
- Go 1.26+
- Модули для `go`/`brew`/`docker` появляются в меню, только если соответствующий инструмент найден в `PATH` — остальное работает и без них

## Установка и запуск

```bash
git clone <repo> cleaner   # или просто скачать/скопировать проект
cd cleaner
go run ./cmd/cleaner
```

Либо собрать бинарник:

```bash
go build -o cleaner ./cmd/cleaner
./cleaner
```

По умолчанию все пути вычисляются от домашнего каталога текущего пользователя — на типичной
macOS-системе ничего настраивать не нужно. Если нужны нестандартные пути, см. раздел
[«Настройка путей под свою систему»](#настройка-путей-под-свою-систему).

## Использование

1. Запустите утилиту — сначала выведется список доступных на этом устройстве модулей, затем появится меню с этими пунктами и «Выход».
2. Стрелками выберите нужный модуль, Enter — подтвердить.
3. Программа покажет текущее состояние (размер/количество файлов).
4. Для Go-кешей дополнительно нужно отметить Space, что чистить (или выбрать «Всё сразу»), Enter — подтвердить выбор.
5. На запрос подтверждения ответьте `Yes`, чтобы выполнить удаление, или `No`, чтобы вернуться в меню без изменений.
6. После выполнения — результат (сколько удалено, если были ошибки — они тоже выводятся), затем снова главное меню.
7. Пункт «Выход» — завершить программу.

## Настройка путей под свою систему

Все пути вычисляются от домашнего каталога пользователя (`os.UserHomeDir()`) и по умолчанию
работают на любой стандартной macOS-системе без правок. Ничего личного/специфичного для
конкретной машины в коде не зашито — переопределить любой путь можно переменной окружения,
не трогая исходники:

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `CLEANER_WORK_DIR` | корень поиска `.idea/httpRequests/*.json` | `$HOME` |
| `CLEANER_LOGS_DIR` | каталог логов приложений | `$HOME/Library/Logs` |
| `CLEANER_DS_STORE_ROOT` | корень поиска `.DS_Store` | `$HOME` |
| `CLEANER_DAVINCI_CACHE_DIR` | каталог render cache DaVinci Resolve | `$HOME/Movies/CacheClip` |
| `CLEANER_DAVINCI_APP_PATH` | путь установки DaVinci Resolve (для проверки, установлено ли приложение) | `/Applications/DaVinci Resolve` |
| `CLEANER_XCODE_DERIVED_DATA_DIR` | каталог DerivedData Xcode | `$HOME/Library/Developer/Xcode/DerivedData` |

Проще всего скопировать `.env.example` в `.env` и раскомментировать/поправить нужные строки —
файл подхватывается автоматически при запуске (`.env` в `.gitignore`, в репозиторий не попадает).
Так же можно просто экспортировать переменные в шелле — они имеют приоритет над `.env`.

`WorkDir` по умолчанию — весь домашний каталог (у "рабочих проектов" нет стандартного места),
так что почти всем стоит задать `CLEANER_WORK_DIR` под свою реальную структуру проектов, чтобы
поиск не обходил весь `$HOME`; остальные пути подходят как есть на типичной системе.

## Архитектура

Проект построен по принципу чистой архитектуры:

```
cmd/cleaner          — точка входа: только сборка зависимостей и запуск, без логики
internal/domain      — чистые данные: entities, enums, специфичные для машины пути (paths), без I/O
internal/usecase/*   — обращение к ОС: exec.Command (go/brew/docker), файловая система
internal/application — вся оркестрация: меню, ввод пользователя, вывод результатов
internal/pkg         — общие внутренние утилиты (например, форматирование размеров в humanize)
```

Каждый модуль очистки — это usecase с интерфейсом `Cleaner`:

```go
type Cleaner interface {
    Status(ctx context.Context) (Status, error)    // предпросмотр: что и сколько будет удалено
    Clean(ctx context.Context) Result               // само удаление
    Available(ctx context.Context) bool              // есть ли на этом устройстве инструмент/директория
}
```

`internal/application` при старте фильтрует пункты меню по `Available`, затем для выбранного модуля вызывает `Status` → показывает предпросмотр → спрашивает подтверждение → вызывает `Clean` → печатает результат. Добавление нового модуля очистки не требует изменения существующих — только новый usecase-пакет и пункт в списке кандидатов в `application.go`.

## Безопасность

- Ничего не удаляется без явного подтверждения.
- Docker-модуль намеренно не использует `-a`/`--volumes` — именованные тома и используемые образы не удаляются.
- `.DS_Store` и логи — регенерируемые файлы, безопасны к удалению.
- Go-кеши, Homebrew, DaVinci render cache и Xcode DerivedData пересоздаются автоматически при следующей сборке/установке/рендере.
